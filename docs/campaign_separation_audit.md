# Campaign production/test separation audit

This audit covers executable repository code, SQL definitions/runbooks and the historical Zapier export at `docs/sources/zapier/exported-zap-2026-05-31T10_27_41.118Z.json`. Source evidence is unchanged. No live Zap, database function, view, role, checkout, report or template was modified or invoked. **Repository tests establish local behavior; they cannot certify all production writers.** Keep the test registry disabled and do not create fake trees until the external gates are signed off.

Both central subscription functions and the campaign fail when their exact candidate count cannot be met. Searches for `trees1`, `user_id IS NULL`, `is_claimed`, UPDATE/INSERT, ORDER/LIMIT and fallback found **no pool-switching fallback in repository allocators**. The historical external routes above are not yet proven safe. In particular, a TEST checkout routed into an unchanged legacy Zap could select a real tree because that SQL does not receive a trusted campaign classification. The database guard cannot identify a Shopify order it has never seen. Thus live routing verification is a release blocker; do not claim that 027 alone makes every existing Zap safe.

Detail lookup does the same. Customer lookup joins underlying tree metadata; verify the live `v_user_trees` definition and permissions in staging. Fake codes and synthetic ocean area/type reinforce the label. No planted date is fabricated.
